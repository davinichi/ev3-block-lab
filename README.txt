EV3 Block Lab — 試作版 0.1.6

0.1.6の変更：停止時刻の診断（停止差は未解決）
補正制御のB/C完了時刻と、25%・50%・75%の位置に達した時刻をEV3本体の時計で記録します。
制御方式そのものは0.1.5から変更していません。この版で停止差が解決したとはしていません。
PCとの通信時間の影響を避け、単独実行後にも測定結果を読み戻せるようにしました。
完了信号を20ms間隔で観測した時刻であり、物理的な停止の厳密な時刻とは異なる場合があります。
転送したプログラムに対応する最後の補正ブロックが、EV3Lab/FB_<識別子>.binへ68バイトの記録を保存します。
同じプログラムの次の実行ではその診断記録だけを更新します。タイムアウトも区別して記録します。
識別子にプロジェクト内容とコンパイラー版を含め、別のプログラムの記録は読み込まないようにしています。
1つのプログラムに補正ブロックが複数ある場合は、最後に完了またはタイムアウトしたブロックの記録です。
上記の保存・読み戻しはソフトウェア上で検証済みで、実機のファイル保存の確認は必要です。

今回の診断手順
1. ページを更新し0.1.6を確認。「停止タイミングを補正（試作）」、B+C、速度20、360度にします。
2. 再転送・照合し、本体で今回の新しいファイルを1回実行します。
3. 接続中に「停止時刻の記録を読む」を押します。開始角度を記録する操作は不要です。
4. B/Cの完了時刻と差、角度を確認。「通信ログ→ログを保存」のファイルを共有します。
同じ記録を繰り返し読むと「前回と同じ記録です」と表示します。
記録の保存に失敗した場合は、今回の記録が出ないことがあります。読めない場合の表示とログを共有してください。

0.1.5の変更：停止タイミングの補正（実機未検証）
右側に「停止タイミングを補正（試作）」を追加しました。選択後に再転送が必要です。
独立した角度目標を残し、EV3本体が20msごとに角度センサーで進み具合を比較します。
先行側の速度を落とし、終点付近は低速にして停止時刻の差を小さくする試作制御です。
この補正も.rbfに含まれ、PCを切り離した単独実行に対応します。
マイブロックの引数、逆回転に対応。同じ種類のモーターを使用してください。
完全に同じ時刻に止まることや実機の精度を保証するものではありません。
電池、負荷、モーターの応答を含む調整には実機テストが必要です。
一定時間進まない場合は、全モーターを停止して低い音を鳴らし、後続のブロックも実行せずプログラムを終了します。
監視時間は角度と速度から余裕をもって計算し、上限3分を超える設定は転送前に拒否します。
簡易モーターモデルでは、360度・速度20・片側応答70%の例で停止時刻の差が減ることを検証しました。
このモデルはEV3の物理挙動を完全に再現するものではなく、実機検証とは区別しています。
確認手順：B+C・速度20・360度にして補正方式を選択→転送→開始角度を記録→本体から実行→終了角度を読む。
回転角度に加え、停止時刻の差が以前より小さいかも確認してください。

0.1.4の変更と診断手順
同期方式の実機での角度ずれが未解決のため、B+Cの標準設定を独立角度制御に戻しました。
同時に動き始め、それぞれの指定角度まで動きますが、終了時刻は一致しない場合があります。
右側の「B+Cの制御」で、従来の同期方式も明示的に選べます（検証用）。変更後は再転送が必要です。
開始前と実行後のモーター角度センサー値を、ブラウザから読み取る診断機能を追加しました。
読み取りだけではモーターは動かず、角度カウントもリセットしません。

診断：B+C、速度20、360度のプログラムを転送・照合してください。
接続したまま右側の「①開始角度を記録」を押し、本体で今回のファイルを1回実行します。
モーター停止後に「③終了角度を読む」を押すと、開始からの実測角度がB/C別に出ます。
計測途中はEV3の再起動や手で軸を回す操作を行わないでください。接続を切ると開始記録を解除します。
標準方式と同期方式のそれぞれで再転送し、毎回開始記録を取り直して計測してください。
値と「通信ログ→ログを保存」のファイルを共有すると、実際のセンサー差分と生成命令を照合できます。
同期の終了時刻と角度を両方そろえる問題は、今回の版で解決確認済みではありません。

0.1.3の修正
同期回転の直前に、対象2ポートの制御用角度カウントをOUTPUT_RESETでゼロにそろえます。
EV3の同期制御は累積角度を比較するため、開始前の値が異なると実際に動く量が変わる可能性がありました。
各B+Cブロックの開始位置を基準に指定角度を回すよう修正しました。
センサー用の累積角度（OUTPUT_GET_COUNT）はリセットしません。
片側に90度の開始オフセットがあるモデルと、負の速度・異なる初期値のモデルで検証しました。
実機での回転角度・同期精度は、修正版を再転送して確認してください。

0.1.2の修正
B+Cの角度指定を、独立した速度制御からEV3のOUTPUT_STEP_SYNC（旋回比0）に変更しました。
2個の回転を同期させ、両方の完了を待ちます。同じ種類のモーターで確認してください。
1個だけの指定は従来のOUTPUT_STEP_SPEEDのままです。
同期命令の生成と引数の検証はソフトウェア上で実施。実機での同期精度は確認が必要です。

0.1.1の修正
標準EV3では、CREATE_DIRは既存フォルダーに対しても0x05を返します。
EV3Labがある場合に2回目以降の転送が止まる問題を修正しました。
0x05の許容はフォルダー作成時に限定し、実際のファイル保存の拒否はエラーとして扱います。
転送成功は、引き続きファイルを読み戻し全バイトが一致した場合のみ表示します。

目的
Chromebookのブラウザで引数付きマイブロックを編集し、標準LEGO EV3へBluetoothで実行ファイルを保存する試作品です。
転送後はファイルを読み戻し、全バイトの一致を確認します。転送ではプログラムを起動しません。
LEGOの標準ファームウェアを対象とし、ファームウェアの書き換えや追加アプリは不要です。

実装済み
・Blocklyによる日本語のブロック編集
・整数引数（最大8個）を持つ、戻り値なしのマイブロック定義と呼び出し
・EV3標準のSUBCALL形式を用いた、独立した.rbfファイルの生成
・A/B/C/D/B+Cのモーター角度・速度指定、完了待ち、停止
・音、待ち時間、回数指定の繰り返し（入れ子対応）
・Chrome Web Serial / Bluetooth Classic SPP経由での転送
・転送ファイルを読み戻して照合
・プロジェクトの自動保存、ファイル保存・読み込み、通信ログの出力

この版に含まれない機能
USBからの直接転送、センサー、条件分岐、一般変数、戻り値、再帰、並列実行、距離cmから回転角への換算、SPIKEプロジェクトとの互換性。
音の長さは1〜30000ミリ秒。待機は0〜60000ミリ秒。繰り返しは0〜1000回。
実機のBluetooth接続および単独実行は未確認です。今回の実機テストが必要です。

実機テスト
1. Chromebookの最新のChromeで公開URLを通常のタブとして開きます。
2. 標準のEV3ファームウェアで起動します。ev3dev/PybricksのSDカードが入っている場合は、電源を切ってカードを外します。
3. EV3のBluetoothとVisibleをオン、iPhone/iPad/iPod設定をオフにします。
4. Chromebookの設定→BluetoothでEV3とペアリング。本体側も承認します。PINは通常1234です。
5. 他のEV3用アプリを閉じ、このツールの「接続する」でEV3のBluetoothシリアルポートを選びます。
6. 「音だけ」を選択して「EV3に転送・照合」。緑色の「照合完了」とファイル名を確認します。
7. 「切断」を押してEV3を再起動。本体のFile NavigationからEV3Labフォルダー内の表示されたファイル名を起動します。
8. 440Hz、待機500ms、880Hzの順に鳴れば、引数を変えたマイブロックを単独実行できています。
9. モーターBのテストは車輪を浮かせて行います。Bポートにモーターを接続し、サンプルを切り替えて転送・照合・切断・再起動を行います。
10. 同じ方向に90度（速度20）、待機500ms、180度（速度30）回れば成功です。
11. 数値を変更して再転送し、変更が反映されることを確認します。編集用プロジェクトを保存して、読み込み直せることも確認してください。

保存先
本体の ../prjs/EV3Lab/Lab_MMDD_HHMMSS_XXXX.rbf 。毎回新しい名前を作ります。
転送したテストファイルは本体に残ります。不要なファイルはEV3本体の操作で削除できます。
ブラウザのローカル保存を消すと編集データを失います。「保存」でプロジェクトファイルも保管してください。

うまくいかないとき
・一覧にEV3がない：OS側のペアリング、Visible、Chromeバージョンを確認。他のEV3アプリを閉じます。
・選択できない：学校管理のChromeでWeb Serialが許可されているか管理者に確認します。
・応答なし：標準ファームウェアで起動し、プログラムを止めて接続し直します。
・フォルダーが見えない：EV3のファイル画面を切り替えるか再起動します。
・ファイルを選んでも動かない：本体の表示・ファームウェアの版・ログを記録します。
問題の報告には「通信ログ→ログを保存」で出たev3-test-log.jsonを共有してください。
このファイルには、プロジェクトの内容、通信の送受信内容、Chromeの情報が含まれます。

手元で起動する場合（開発用）
Node.jsを用意し、このフォルダーで npm start を実行します。
http://localhost:8765 をChromeで開いてください。
別の端末の http://IPアドレス ではWeb Serialを使えないため、ChromebookからはHTTPSの公開URLを使用します。
index.htmlのダブルクリックによるfile://での起動は対応していません。
依存ライブラリのBlocklyはdist/vendorに同梱しています。追加のインストールは不要です。
検証は npm test 。最後の仕様照合テストのみ、外部の公式ファームウェア資料のチェックアウトがあるときに実行します。

技術上の検証範囲
署名LEGO、RBFサイズ、バージョン104、VMTHREAD/SUBCALLヘッダー、IN32引数、定数/ローカル変数のエンコードを確認。
生成済みバイナリを別の簡易インタープリターで読み、異なる引数、負の速度、入れ子の繰り返しを確認。
模擬応答でパケット分割・結合、複数パケット転送、ファイル末尾、読み戻し不一致、エラー応答、タイムアウトを確認。
簡易インタープリターと模擬応答は、実機での確認の代わりにはなりません。
